# ciTY展馆 — 接口文档（登录模块）

---

## 零、前后端统一规范

### 一、localStorage 存储规范

| 存储内容 | 是否存储 | 说明 |
|------|------|------|
| token（JWT） | ✅ 存 | 唯一持久化存储的字段 |
| 用户信息（昵称、头像、id、status 等） | ❌ 不存 | 只放内存（Vue/React state），禁止写 localStorage |

**为什么不能存用户信息？**

1. **数据不同步**：用户在别的设备改头像/昵称、后台封禁账号，本地缓存还是旧数据，页面展示错误
2. **安全风险**：status、角色、userId 存本地，用户可手动改 localStorage 伪造身份
3. **维护麻烦**：每次改完个人信息还要手动更新本地缓存，容易漏

### 二、页面刷新 / 重新打开标准流程

```
页面加载
  → 读 localStorage 取 token
  → 无 token → 跳登录页
  → 有 token → 调 GET /api/app/profile（或 /api/admin/profile）
  → 后端校验 JWT 是否有效、账号是否封禁
    → 校验失败 → 清 token，跳登录页
    → 校验成功 → 返回最新用户信息，前端放内存渲染页面
```

**登录接口返回用户信息的作用**：仅用于登录成功后首次页面渲染，属于临时快照，刷新页面后必须重新调 `/profile` 拿实时数据。

### 三、接口路径规范

- **全部接口强制带 `/api/` 前缀**，不存在不带 `/api/` 的接口
- 格式：`/api/{身份}/{模块}/{操作}`
- C端：`/api/app/...`
- B端：`/api/admin/...`
- 忘记密码：`/api/...`（前端传 role 区分身份，后端按 role 查对应表）

## 一、C端普通用户接口

### 1. 用户注册 🔓

- **Path**：`/api/app/register`
- **Method**：`POST`
- **描述**：手机号+密码注册，成功自动登录返回 Token 和用户信息（仅用于首次渲染）

**Body**：
```json
{
  "phone": "13800138000",
  "password": "123456"
}
```

| 参数 | 类型 | 必须 | 备注 |
|------|------|------|------|
| phone | string | 是 | 手机号，11位数字 |
| password | string | 是 | 密码，6-16位 |

**成功返回**：
```json
{
  "code": 200,
  "data": {
    "id": 1,
    "phone": "13800138000",
    "nickname": "138****8000",
    "token": "eyJhbGciOiJIUzI1NiIs..."
  },
  "msg": "注册成功"
}
```

---

### 2. 用户登录 🔓

- **Path**：`/api/app/login`
- **Method**：`POST`
- **描述**：手机号+密码登录

**Body**：
```json
{
  "phone": "13800138000",
  "password": "123456"
}
```

| 参数 | 类型 | 必须 | 备注 |
|------|------|------|------|
| phone | string | 是 | 手机号 |
| password | string | 是 | 密码 |

**成功返回**：
```json
{
  "code": 200,
  "data": {
    "id": 1,
    "phone": "13800138000",
    "nickname": "小明",
    "token": "eyJhbGciOiJIUzI1NiIs..."
  },
  "msg": "登录成功"
}
```

**失败返回**：
```json
{ "code": 400, "data": null, "msg": "账号或密码错误" }
```

---

### 3. 获取个人信息 🔒

- **Path**：`/api/app/profile`
- **Method**：`GET`
- **描述**：页面刷新/重新打开时调用，前端只有 token，靠此接口拉最新用户信息

**Headers**：`Authorization: Bearer <token>`

**成功返回**：
```json
{
  "code": 200,
  "data": {
    "id": 1,
    "phone": "13800138000",
    "nickname": "小明",
    "status": 0,
    "create_time": "2026-07-19 12:00:00"
  },
  "msg": "success"
}
```

---

### 4. 修改个人信息 🔒

- **Path**：`/api/app/profile`
- **Method**：`PUT`
- **描述**：修改昵称，手机号不支持修改

**Headers**：`Authorization: Bearer <token>`

**Body**：
```json
{
  "nickname": "新昵称"
}
```

| 参数 | 类型 | 必须 | 备注 |
|------|------|------|------|
| nickname | string | 是 | 新昵称 |

## 三、公共接口（忘记密码，buyer/admin 共用）

> 测试环境：验证码恒为 `666666`，后端直接比对即可，不需要真实发送短信。

### 8. 发送验证码 🔓

- **Path**：`/api/send-code`
- **Method**：`POST`
- **描述**：输入手机号+身份，后端在对应表中查找，找到则"发送"验证码（测试环境不发，直接返回成功）

**Body**：
```json
{
  "phone": "13800138000",
  "role": "user/admin"
}
```

| 参数 | 类型 | 必须 | 备注 |
|------|------|------|------|
| phone | string | 是 | 手机号 |
| role | string | 是 | user/ admin |

**返回**：
```json
{ "code": 200, "data": null, "msg": "验证码已发送" }
```
```json
{ "code": 400, "data": null, "msg": "手机号不存在" }
```

---

### 9. 验证码校验 🔓

- **Path**：`/api/verify-code`
- **Method**：`POST`
- **描述**：前端带手机号+验证码+身份过来。后端校验：① 验证码是否为 `666666` ② 该手机号在对应 role 的表中是否存在。两项都通过才算成功，**后端不返回 role**。

**Body**：
```json
{
  "phone": "13800138000",
  "code": "666666",
  "role": "user/admin"
}
```

| 参数 | 类型 | 必须 | 备注 |
|------|------|------|------|
| phone | string | 是 | 手机号 |
| code | string | 是 | 验证码（测试环境填 `666666`） |
| role | string | 是 | user/ admin，前端从忘记密码入口页面已知 |

**返回**：
```json
{ "code": 200, "data": null, "msg": "校验通过" }
```
```json
{ "code": 400, "data": null, "msg": "验证码错误" }
```
```json
{ "code": 400, "data": null, "msg": "当前账号不存在" }
```

---

### 10. 重置密码 🔓

- **Path**：`/api/reset-password`
- **Method**：`PUT`
- **描述**：校验通过后，前端带手机号+身份+新密码来更新。后端根据 role 更新对应表，更新前再次校验该手机号在对应表中存在。

**Body**：
```json
{
  "phone": "13800138000",
  "role": "user",
  "password": "654321"
}
```

| 参数 | 类型 | 必须 | 备注 |
|------|------|------|------|
| phone | string | 是 | 手机号 |
| role | string | 是 | user / admin |
| password | string | 是 | 新密码，6-16位 |

**返回**：
```json
{ "code": 200, "data": null, "msg": "密码修改成功" }
```

## 附录二：接口与数据库表对应

| 编号 | Path | 数据库操作 |
|------|------|------|
| 1 | `/api/app/register` | `buyer_user` INSERT |
| 2 | `/api/app/login` | `buyer_user` SELECT |
| 3 | `/api/app/profile` GET | `buyer_user` SELECT |
| 4 | `/api/app/profile` PUT | `buyer_user` UPDATE |
| 5 | `/api/admin/login` | `admin_user` SELECT |
| 6 | `/api/admin/profile` GET | `admin_user` SELECT |
| 7 | `/api/admin/profile` PUT | `admin_user` UPDATE |
| 8 | `/api/send-code` | 按 role 查 `buyer_user` 或 `admin_user` SELECT |
| 9 | `/api/verify-code` | 按 role 查对应表校验 phone 是否存在 + 验证码比对 |
| 10 | `/api/reset-password` | 按 role 分别 UPDATE `buyer_user` / `admin_user` |
