## 零、统一规范

### 一、响应格式

所有接口统一返回 `Result<T>`：

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | Integer | 1=成功，0=失败 |
| `msg` | String | 提示文案，成功时固定为 `操作成功` |
| `data` | T | 业务数据，失败时为 `null` |

### 二、分页规范

**请求参数**：

| 参数名 | 类型 | 必须 | 默认值 | 说明 |
|--------|------|------|--------|------|
| page | Integer | 否 | 1 | 页码，从 1 开始 |
| pageSize | Integer | 否 | 10 | 每页条数，**最大 50** |

**返回结构**（`PageResult<T>`）：

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": {
    "total": 23,
    "pages": 3,
    "page": 1,
    "pageSize": 10,
    "list": []
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `total` | Long | 总记录数 |
| `pages` | Integer | 总页数 |
| `page` | Integer | 当前页码 |
| `pageSize` | Integer | 每页条数 |
| `list` | Array | 当前页数据 |

### 三、认证规范

| 标识 | 含义 |
|------|------|
| 🔓 | 免登录可访问 |
| 🔒 | 必须带 token |

**本模块 5 个接口全部免登录**，以下路径必须加入 `WebMvcConfiguration` 的 `excludePathPatterns`：

```
/api/app/exhibitions/page
/api/app/galleries/page
/api/app/dict/exhibition-types
/api/app/dict/gallery-types
/api/app/dict/cities
```

### 四、展览展出状态

**不落库**，由 `start_date` / `end_date` 与 `CURDATE()` 实时判断：

| 状态值 | 含义 | 判断条件 |
|---|---|---|
| `current` | 正在展出 | `start_date <= CURDATE() <= end_date` |
| `future` | 即将展出 | `start_date > CURDATE()` |
| `past` | 往期展出 | `end_date < CURDATE()` |

### 五、列表页交互约定

**「全部展览」主页面有三个区块**（正在展出 / 即将展出 / 往期展出），每个区块显示 **2 张卡片** + 右上角「查看全部」。

**不做区块聚合接口**，前端并行调 3 次同一接口，用 `status` 区分：

```
进入「全部展览」页
  ├── GET /api/app/exhibitions/page?status=current&pageSize=2   → 「正在展出」区块
  ├── GET /api/app/exhibitions/page?status=future&pageSize=2    → 「即将展出」区块
  └── GET /api/app/exhibitions/page?status=past&pageSize=2      → 「往期展出」区块

点击某区块右上角「查看全部」
  └── 跳转到同一个列表页，带上 status 参数
      GET /api/app/exhibitions/page?status=current&page=1&pageSize=10
```

**好处**：三个区块共用一个接口，不需要为「查看全部」单独做 3 个页面，也不需要额外的聚合接口。

## 一、字典接口

### 1. 获取展览类型字典 🔓

- **Path**：`/api/app/dict/exhibition-types`
- **Method**：`GET`
- **描述**：返回「全部展览」页顶部**「展览类型」下拉**的选项列表

**参数**：无

**成功返回**：

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": [
    { "value": 5, "label": "摄影展览" },
    { "value": 4, "label": "雕塑展览" },
    { "value": 3, "label": "古典展览" },
    { "value": 2, "label": "当代展览" },
    { "value": 1, "label": "综合展览" }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `value` | Integer | 传给列表接口的 `type` 参数值 |
| `label` | String | 下拉框显示的中文名 |

**完整取值对照表**（前端下拉顺序建议按此排列）：

| value | label |
|---|---|
| 1 | 综合展览 |
| 2 | 当代展览 |
| 3 | 古典展览 |
| 4 | 雕塑展览 |
| 5 | 摄影展览 |

> ⚠️ **「全部类型」不在返回列表里**。它是前端下拉的第一项，选中时**不传 `type` 参数**（即查全部）。
> ⚠️ 中文名由**后端字典接口**统一维护，**前端不要硬编码**，否则以后改分类名要改两端。

### 3. 获取城市字典 🔓

- **Path**：`/api/app/dict/cities`
- **Method**：`GET`
- **描述**：返回顶部导航栏与筛选栏的**「城市」下拉**选项

**参数**：无

**成功返回**：

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": ["南京", "苏州", "无锡"]
}
```

**实现说明**（二选一，推荐方案 A）：

| 方案 | 做法 |
|---|---|
| **A** | `SELECT DISTINCT city FROM gallery WHERE status = 0 ORDER BY city` —— 只返回**有美术馆的城市**，无需额外维护 |
| B | 若有 `city` 字典表，从该表取 |

> 方案 A 的好处：不会出现「城市下拉里选了一个没有任何美术馆的城市」的尴尬。

## 二、全部展览列表 🔓

- **Path**：`/api/app/exhibitions/page`
- **Method**：`GET`
- **描述**：「正在展出 / 即将展出 / 往期展出」三个区块共用，也用做「查看全部」的完整列表页

**参数**：

| 参数名 | 类型 | 必须 | 默认值 | 说明 |
|--------|------|------|--------|------|
| status | String | 否 | `current` | 展出状态：`current` / `future` / `past` |
| type | Integer | 否 | - | 展览类型，取值见接口 1。**不传=全部类型** |
| city | String | 否 | - | 城市，不传=全部城市 |
| keyword | String | 否 | - | 展览标题模糊搜索（对应「搜索展览」输入框） |
| sort | String | 否 | `default` | 排序：`default` 综合 / `priceAsc` 价格升序 / `priceDesc` 价格降序 |
| page | Integer | 否 | 1 | 页码 |
| pageSize | Integer | 否 | 10 | 每页条数，最大 50。**主页面区块传 2** |

**成功返回**：

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": {
    "total": 23,
    "pages": 3,
    "page": 1,
    "pageSize": 10,
    "list": [
      {
        "id": 1,
        "title": "咫尺千里",
        "posterImage": "/static/mock/exhibition/zhichi.jpg",
        "galleryId": 1,
        "galleryName": "江苏省美术馆",
        "startDate": "2026-05-01",
        "endDate": "2026-08-02",
        "price": 58.00,
        "status": "current",
        "type": 2,
        "typeName": "当代展览",
        "isHot": 1
      },
      {
        "id": 2,
        "title": "世界珍宝",
        "posterImage": "/static/mock/exhibition/treasure.jpg",
        "galleryId": 2,
        "galleryName": "南京博物馆",
        "startDate": "2026-05-19",
        "endDate": "2026-08-25",
        "price": 38.00,
        "status": "current",
        "type": 3,
        "typeName": "古典展览",
        "isHot": 0
      }
    ]
  }
}
```

**卡片字段说明**（对照原型卡片）：

| 原型卡片元素 | 返回字段 |
|---|---|
| 上方海报图 | `posterImage` |
| 「展览：咫尺千里」 | `title` |
| 「美术馆：江苏省美术馆」 | `galleryName`（JOIN `gallery` 取得） |
| 「时间：05.01——08.02」 | `startDate` + `endDate`（前端自己拼接） |
| 右下「¥58」 | `price` |

| 其他字段 | 类型 | 说明 |
|---|---|---|
| `id` | Long | 展览 ID，点击卡片跳详情页 |
| `galleryId` | Long | 所属美术馆 ID |
| `status` | String | `current` / `future` / `past`，由 Service 实时计算 |
| `type` / `typeName` | Integer / String | 展览分类值与中文名 |
| `isHot` | Integer | 是否热门，0/1 |

**失败返回**：

```json
{
  "code": 0,
  "msg": "系统异常",
  "data": null
}
```

**核心 SQL**：

```sql
SELECT e.id, e.title, e.poster_image, e.start_date, e.end_date,
       e.price, e.type, e.is_hot,
       g.id AS gallery_id, g.name AS gallery_name
FROM exhibition e
JOIN gallery g ON g.id = e.gallery_id
WHERE 1 = 1
  <!-- ① 展出状态：三选一，用 choose 保证互斥 -->
  <choose>
    <when test='dto.status == "future"'> AND e.start_date &gt; CURDATE() </when>
    <when test='dto.status == "past"'>   AND e.end_date &lt; CURDATE()  </when>
    <otherwise> AND e.start_date &lt;= CURDATE() AND e.end_date &gt;= CURDATE() </otherwise>
  </choose>
  <!-- ② 可选筛选 -->
  <if test='dto.type != null'> AND e.type = #{dto.type} </if>
  <if test='dto.city != null and dto.city != ""'> AND g.city = #{dto.city} </if>
  <if test='dto.keyword != null and dto.keyword != ""'>
    AND e.title LIKE CONCAT('%', #{dto.keyword}, '%')
  </if>
ORDER BY e.is_hot DESC, e.sort_order DESC, e.start_date ASC, e.id ASC
LIMIT #{offset}, #{pageSize}
```

> `sort = priceAsc` 时把 `ORDER BY` 换成 `e.price ASC, e.id ASC`；`priceDesc` 同理。**末尾的 `e.id ASC` 不能省**。

**数据来源**：`exhibition` JOIN `gallery`

**卡片字段说明**（对照原型卡片）：

| 原型卡片元素 | 返回字段 |
|---|---|
| 上方封面图 | `coverImage` |
| 「南京市美术馆」 | `name` |
| 「⊙南京市秦淮区四条巷12号」 | `address`（**已含城市与区县**，前端直接显示） |
| 「正在展出：1场」 | `exhibitionCount` |
| 右下「查看详情 >」 | 用 `id` 跳美术馆详情页 |

**页面标题**：「南京全部美术馆」+ 副标题「南京 · 共有 **12** 个美术馆」——其中数字取本接口的 `total`。

```json
{
  "code": 0,
  "msg": "系统异常",
  "data": null
}
```

**核心 SQL**：

```sql
SELECT id, name, cover_image, address, city, exhibition_count, type
FROM gallery
WHERE status = 0
  <if test='dto.type != null'> AND type = #{dto.type} </if>
  <if test='dto.city != null and dto.city != ""'> AND city = #{dto.city} </if>
  <if test='dto.keyword != null and dto.keyword != ""'>
    AND name LIKE CONCAT('%', #{dto.keyword}, '%')
  </if>
ORDER BY exhibition_count DESC, id ASC
LIMIT #{offset}, #{pageSize}
```

> `status = 0` 是**必须的**（只显示正常营业的馆，闭馆维护的不展示）。

**数据来源**：`gallery` 表

## 附录四：开发注意事项

| # | 注意事项 |
|---|---------|
| 1 | 本模块 5 个路径必须加入 JWT 拦截器 `excludePathPatterns`，否则返回 401 |
| 2 | **「全部类型」不传参**，不要把「全部」做成一个 value（比如 0）传后端 |
| 3 | 展出状态用 `<choose>` 保证三选一互斥，**不要写三个独立 `<if>`**，否则条件叠加会查错 |
| 4 | `ORDER BY` 末尾必须加唯一列（`id ASC`）兜底，否则翻页会出现重复记录 |
| 5 | `galleryName` 通过 JOIN 获取，**禁止在循环里查数据库**（N+1） |
| 6 | `pageSize` 上限压到 50，防止前端传超大值拖库 |
| 7 | 美术馆列表必须带 `WHERE status = 0`，闭馆的馆不展示 |
| 8 | `exhibition_count` 是冗余字段，直接读，不要改成实时 COUNT |
| 9 | 「全部展览」主页面 3 个区块是 **3 次独立请求**，不要做成串行等待 |
| 10 | 类型字典的**中文名由后端维护**，前端禁止硬编码 `1→综合展览` 这类映射 |
