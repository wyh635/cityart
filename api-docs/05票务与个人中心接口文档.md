## 零、统一规范

### 一、响应格式

统一返回 `Result<T>`：

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": {}
}
```

| code | 含义 |
|------|------|
| `1` | 成功 |
| `0` | 失败 |

### 二、分页规范

**请求**：`page`（默认 1）、`pageSize`（默认 10，最大 50）

**返回**（`PageResult<T>`）：

```json
{
  "total": 5,
  "pages": 1,
  "page": 1,
  "pageSize": 10,
  "list": []
}
```

### 三、认证规范

| 标识 | 含义 |
|------|------|
| 🔓 | 免登录可访问 |
| 🔒 | **必须带 token**，后端从 `BaseContext.getCurrentId()` 取 `userId` |

本模块**除票种和日历查询外，全部需要登录**。🔒 接口的 `userId` **一律从 token 取，禁止由前端传入**（否则用户能查别人的订单）。

白名单只需放行两个（其余 `/api/app/**` 默认被拦截器保护）：

```
/api/app/ticket-types/*        ← 若票种接口挂在展览路径下，按实际路径调整
/api/app/exhibitions/*/calendar
```

> ⚠️ 本模块大部分接口在 `/api/app/orders/**`、`/api/app/personal/**`、`/api/app/favorites/**` 下，**都不要加入白名单**，保持需要登录。

### 四、订单状态

| 值 | 名称 | 对应原型 tab | 库存状态 |
|---|---|---|---|
| 1 | 待支付 | 待支付 | 已锁定，30 分钟超时释放 |
| 2 | 已支付 | 已支付 | 已扣减 |
| 3 | 已取消 | 已取消 | 已释放 |
| 4 | 已退款 | 已退款 | 已释放 |
| 5 | 已完成 | — | 已核销入场 |

### 五、票务模型（三条硬规则）

1. **多票种** —— 一个展览多个票种、多个价格，价格与库存以 `ticket_type` 表为准
2. **日历只放指定日期** —— `exhibition_calendar` 里没有记录的日期**不发售**
3. **一单一码** —— 一个订单一个二维码，**核销按整单**（买 2 张一起入场）

### 六、购物流程

```
展览详情页 → 点「购票」
   │
   ├─ GET  /api/app/exhibitions/{id}/ticket-types    选票种（4 种价格）
   ├─ GET  /api/app/exhibitions/{id}/calendar        选观展日期（含「已售完」）
   │
   ▼ 点「确认下单」（必选填完才可点）
POST /api/app/orders
   │
   ▼ 跳支付页
GET  /api/app/orders/{orderNo}        展示订单号 + 30 分钟倒计时 + 应付金额
POST /api/app/orders/{orderNo}/pay    回去支付 → 返回二维码/支付参数
   │
   ▼ 支付结果
   成功 → status=2，生成 qr_code + expire_time
   失败 → 留在支付页可重试
   │
   ▼ 支付成功后可查看
   票夹（二维码）/ 我的订单 / 看展记录（核销后）
```

## 一、票种与日历查询

### 1. 获取展览的票种列表 🔓

- **Path**：`/api/app/exhibitions/{id}/ticket-types`
- **Method**：`GET`
- **描述**：购票页「选择票种 TYPE」区域

**Path 参数**：`id` — 展览 ID

**成功返回**：

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": [
    { "id": 1, "name": "成人票", "price": 58.00, "remaining": 500, "limitPerUser": 5 },
    { "id": 2, "name": "老人票", "price": 38.00, "remaining": 300, "limitPerUser": 5 },
    { "id": 3, "name": "学生票", "price": 38.00, "remaining": 300, "limitPerUser": 5 },
    { "id": 4, "name": "儿童票", "price": 38.00, "remaining": 200, "limitPerUser": 5 }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | Long | 票种 ID，下单时传 `ticketTypeId` |
| `name` | String | 票种名称（原型显示「成人票」） |
| `price` | Number | **该票种单价**（原型「¥58」） |
| `remaining` | Integer | 剩余库存 = `total_stock - sold_count`，0 时置灰不可选 |
| `limitPerUser` | Integer | 每人限购（原型文案「每人至多可购五张」） |

**SQL**：

```sql
SELECT id, name, price, total_stock - sold_count AS remaining, limit_per_user
FROM ticket_type
WHERE exhibition_id = #{id} AND status = 0
ORDER BY sort DESC, id ASC;
```

### 2. 获取展览的观展日期 🔓

- **Path**：`/api/app/exhibitions/{id}/calendar`
- **Method**：`GET`
- **描述**：购票页「选择观展日期 DATE」下拉

**Path 参数**：`id` — 展览 ID

**成功返回**：

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": [
    { "date": "2026-10-16", "weekDay": "周四", "remaining": 200, "soldOut": false },
    { "date": "2026-10-17", "weekDay": "周五", "remaining": 200, "soldOut": false },
    { "date": "2026-10-18", "weekDay": "周六", "remaining": 0,   "soldOut": true  },
    { "date": "2026-10-19", "weekDay": "周日", "remaining": 200, "soldOut": false },
    { "date": "2026-10-21", "weekDay": "周二", "remaining": 200, "soldOut": false }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `date` | String | 日期 `yyyy-MM-dd` |
| `weekDay` | String | 星期，前端显示「（周四）」。**由后端算**，避免前端拼 |
| `remaining` | Integer | 当日剩余票数 |
| `soldOut` | Boolean | **`true` 时前端置灰**（原型「已售完」） |

**SQL**：

```sql
SELECT calendar_date,
       total_stock - sold_count AS remaining,
       CASE WHEN total_stock - sold_count <= 0 OR status = 1 THEN 1 ELSE 0 END AS sold_out
FROM exhibition_calendar
WHERE exhibition_id = #{id} AND calendar_date >= CURDATE()
ORDER BY calendar_date ASC;
```

> 📌 **只返回日历表里有的日期**。没有记录的日期前端根本不显示 —— 这就是「只放 5 天的票」的实现。

## 二、下单

### 3. 创建订单（确认下单） 🔒

- **Path**：`/api/app/orders`
- **Method**：`POST`
- **描述**：购票页「确认下单」。生成待支付订单，**同时锁定两个维度的库存**

**Body**：

```json
{
  "exhibitionId": 1,
  "ticketTypeId": 1,
  "visitDate": "2026-10-17",
  "quantity": 1,
  "contactName": "熊籽",
  "contactPhone": "13800138000"
}
```

| 参数 | 类型 | 必须 | 说明 |
|------|------|------|------|
| exhibitionId | Long | 是 | 展览 ID |
| ticketTypeId | Long | 是 | 票种 ID，来自接口 1 |
| visitDate | String | 是 | 观展日期 `yyyy-MM-dd`，必须在接口 2 返回的列表内 |
| quantity | Integer | 是 | 数量，≥1 且 ≤ `limitPerUser` |
| contactName | String | 是 | 联系人 |
| contactPhone | String | 是 | 手机号，11 位 |

**成功返回**：

```json
{
  "code": 1,
  "msg": "下单成功",
  "data": {
    "orderNo": "20261001000001",
    "totalAmount": 58.00,
    "status": 1,
    "payExpireTime": "2026-10-01 15:30:00",
    "remainingSeconds": 1800
  }
}
```

| 字段 | 说明 |
|------|------|
| `orderNo` | 订单号，跳支付页用 |
| `totalAmount` | 订单总金额 |
| `status` | 固定为 1（待支付） |
| `payExpireTime` | 支付超时时间（下单 + 30 分钟） |
| `remainingSeconds` | **剩余支付秒数**，前端倒计时直接用，避免客户端时间不准 |

**失败返回（按校验顺序）**：

```json
{ "code": 0, "msg": "票种不存在或已停售", "data": null }
{ "code": 0, "msg": "所选日期不可预约", "data": null }
{ "code": 0, "msg": "所选日期已售完", "data": null }
{ "code": 0, "msg": "库存不足", "data": null }
{ "code": 0, "msg": "超出限购数量，每人最多可购 5 张", "data": null }
```

**下单要做的事（顺序不能乱）**：

```
① 校验票种存在且在售          → ticket_type
② 校验日期在日历里且未售完     → exhibition_calendar
③ 校验限购：该用户在该展览已购数量 + quantity ≤ limit_per_user
④ 扣票种库存（条件更新，判断影响行数）
⑤ 扣日历库存（条件更新，判断影响行数）
⑥ 生成 order_no，INSERT 订单（status=1, pay_expire_time = now + 30min）
⑦ 返回订单号 + 剩余秒数
```

**两个维度的扣减 SQL（都必须判断影响行数）**：

```sql
-- ④ 票种维度
UPDATE ticket_type SET sold_count = sold_count + #{quantity}
WHERE id = #{ticketTypeId} AND status = 0
  AND total_stock - sold_count >= #{quantity};
-- 受影响行数 = 0 → 抛「库存不足」，事务回滚

-- ⑤ 日期维度
UPDATE exhibition_calendar SET sold_count = sold_count + #{quantity}
WHERE exhibition_id = #{exhibitionId} AND calendar_date = #{visitDate}
  AND total_stock - sold_count >= #{quantity};
-- 受影响行数 = 0 → 抛「所选日期已售完」，事务回滚
```

> ⚠️ **必须包在同一个 `@Transactional` 里**。任一失败要回滚前面的扣减，否则库存会凭空少掉。

> ⚠️ **`order_no` 不能用自增 id**。建议 `yyyyMMdd` + 序列/雪花，长度 ≤ 32，靠 `uk_order_no` 保证唯一。

### 5. 获取支付参数（去支付） 🔒

- **Path**：`/api/app/orders/{orderNo}/pay`
- **Method**：`POST`
- **描述**：支付页「去支付」按钮

**Body**：

```json
{ "payType": 1 }
```

| 参数 | 类型 | 必须 | 说明 |
|------|------|------|------|
| payType | Integer | 是 | 1-微信支付 2-支付宝 |

**成功返回**：

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": {
    "orderNo": "20261001000001",
    "payType": 1,
    "totalAmount": 58.00,
    "qrCodeUrl": "weixin://wxpay/bizpayurl?pr=xxxxxx",
    "prepayId": "wx201410272009395522657a690389285100",
    "timeStamp": "1759300000",
    "nonceStr": "abc123",
    "package": "prepay_id=wx20141027...",
    "signType": "RSA",
    "paySign": "oR9d8PuhnIc+YZ8cBHFCwfgpaK9gd7vaRvkYD7rthRAZ..."
  }
}
```

| 字段 | 说明 |
|------|------|
| `qrCodeUrl` | **扫码支付二维码内容**（原型弹窗里的二维码） |
| `timeStamp` / `nonceStr` / `package` / `paySign` | 小程序内调起支付用 |
| `prepayId` | 预支付交易会话标识 |

**失败返回**：

```json
{ "code": 0, "msg": "订单状态错误", "data": null }
{ "code": 0, "msg": "订单已超时，请重新下单", "data": null }
```

**校验规则**：

- 只有 `status = 1`（待支付）且 `NOW() < pay_expire_time` 的订单能发起支付
- 超时订单先自动取消（`status → 3` + 释放库存），再返回「订单已超时」

### 6. 支付结果回调 🔓

- **Path**：`/api/app/orders/pay-notify`
- **Method**：`POST`
- **描述**：微信/支付宝异步通知。**此接口不套 `Result`**，按支付平台要求返回

**处理逻辑**：

```
① 验签（支付平台签名）
② 按 out_trade_no 找订单
③ 幂等：UPDATE ... WHERE order_no = ? AND status = 1（影响行数 0 直接返回成功）
④ 成功：status → 2，写 pay_time / pay_type
⑤ 生成 qr_code（一单一码）与 expire_time（如 visit_date + 45 天）
⑥ 返回平台要求的成功标识
```

**成功响应**（微信）：`{ "code": "SUCCESS", "message": "成功" }`

### 8. 取消订单 🔒

- **Path**：`/api/app/orders/{orderNo}/cancel`
- **Method**：`PUT`
- **描述**：待支付订单主动取消

**Body**：

```json
{ "cancelReason": "不想看了" }
```

**成功返回**：`{ "code": 1, "msg": "已取消", "data": null }`

**失败返回**：`{ "code": 0, "msg": "订单状态错误", "data": null }`

**必须做的事**：

```sql
-- ① 条件更新，防重复取消
UPDATE exhibition_order SET status = 3, cancel_time = NOW(), cancel_reason = #{reason}
WHERE order_no = #{orderNo} AND user_id = #{userId} AND status = 1;
-- 受影响行数 = 0 → 抛「订单状态错误」

-- ② 释放两个维度的库存
UPDATE ticket_type SET sold_count = sold_count - #{quantity} WHERE id = #{ticketTypeId};
UPDATE exhibition_calendar SET sold_count = sold_count - #{quantity}
WHERE exhibition_id = #{exhibitionId} AND calendar_date = #{visitDate};
```

### 9. 申请退款 🔒

- **Path**：`/api/app/orders/{orderNo}/refund`
- **Method**：`POST`
- **描述**：订单卡「申请退款」按钮

**Body**：

```json
{ "refundReason": "行程有变" }
```

**成功返回**：`{ "code": 1, "msg": "退款申请已提交", "data": null }`

**校验规则**（来自观展须知「仅已支付订单可申请退款」）：

| 条件 | 不满足时的提示 |
|---|---|
| `status = 2`（已支付） | 订单状态错误 |
| 未核销（`use_time IS NULL`） | 已核销的订单不可退款 |
| 未过展期 | 展览已结束，不可退款 |
| `refund_status = 0` | 退款申请处理中 |

**退款成功后**：`status → 4`、`refund_status = 2`、写入 `refund_amount`，并**释放两个维度的库存**。

## 四、我的订单 · 票夹 · 看展记录

## 附录四：开发注意事项

| # | 注意事项 |
|---|---------|
| 1 | 🔒 接口的 `userId` **一律从 token 取**，禁止前端传入，否则能查别人的订单 |
| 2 | **下单必须包 `@Transactional`**：两个维度扣库存 + 插订单，任一失败全部回滚 |
| 3 | 扣库存必须用「**条件更新 + 判断影响行数**」，不能用「先查再改」，否则并发超卖 |
| 4 | **下单校验顺序**：票种 → 日期 → 限购 → 扣票种库存 → 扣日历库存 → 插订单 |
| 5 | `order_no` **不能用自增 id**，用 `yyyyMMdd` + 序列/雪花 |
| 6 | 取消 / 退款必须**同时释放两个维度的库存**（`ticket_type` 和 `exhibition_calendar`） |
| 7 | 订单状态变更一律用 `UPDATE ... WHERE status = 旧值` 条件更新，防重复操作 |
| 8 | 支付回调必须**幂等**：`WHERE order_no = ? AND status = 1`，重复回调直接返回成功 |
| 9 | `remainingSeconds` 由**后端算**，前端不要用本地时间减（否则改系统时间可绕过倒计时） |
| 10 | `phone` 返回**脱敏格式**，不要下发完整手机号 |
| 11 | 一单一码：核销**整单**（`status → 5`，写 `use_time`），核销成功同步 `user.visit_count + 1` |
