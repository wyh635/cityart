## 零、统一规范

### 一、响应格式

统一返回 `Result<T>`：

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": {}
}
```

| code | 含义 |
|------|------|
| `1` | 成功 |
| `0` | 失败 |

### 二、路径规范

- **全部带 `/api/admin/` 前缀**（与 C 端 `/api/app/` 区分）
- 登录接口：`POST /api/admin/login`（见 01 文档，B 端管理员表 `admin`）

### 三、认证规范

| 标识 | 含义 |
|------|------|
| 🔓 | 免登录（仅登录接口） |
| 🔒 | 必须带 token |

**除登录外全部需要 token**。拦截器注册路径：

```java
registry.addInterceptor(jwtTokenAdminInterceptor)
        .addPathPatterns("/api/admin/**")
        .excludePathPatterns("/api/admin/login");
```

> ⚠️ 当前项目只有 C 端拦截器 `JwtTokenUserInterceptor` 拦截 `/api/app/**`。
> **B 端需要另写一个 `JwtTokenAdminInterceptor`**，用 `cityart.jwt.admin-secret-key` 验签，
> 并把 `adminId` 写入独立的 ThreadLocal（不要和 C 端的 `BaseContext` 混用）。

B 端 token 请求头名由 `cityart.jwt.admin-token-name` 决定，当前 yml 里是 `token`。

### 四、分页规范

**请求**：`page`（默认 1）、`pageSize`（默认 10，最大 50）

**返回**（`PageResult<T>`）：

```json
{
  "total": 23,
  "pages": 3,
  "page": 1,
  "pageSize": 10,
  "list": []
}
```

### 五、后台通用筛选

数据看板、展览列表、扫码核销、票务数据四个页面都有同一组筛选：

| 参数 | 说明 |
|------|------|
| `city` | 城市，来自接口 2；不传=全部城市 |
| `status` | 状态（页面含义不同，见各接口） |
| `type` | 展览类型，来自接口 3；不传=全部类型 |
| `keyword` | 搜索框内容 |

### 六、日期范围

「今日 / 本周 / 本月」等时间范围作为 `rangeType` 传参，**由后端算起止日期**，前端不传具体时间：

| rangeType | 含义 |
|---|---|
| `today` | 今天 |
| `week` | 本周（周一到今天） |
| `month` | 本月（1 号到今天） |
| `custom` | 自定义（需同时传 `startDate` / `endDate`） |

## 一、数据看板

### 1. 获取看板核心指标 🔒

- **Path**：`/api/admin/dashboard/overview`
- **Method**：`GET`
- **描述**：数据看板顶部三张卡片

**参数**：

| 参数名 | 类型 | 必须 | 默认值 | 说明 |
|--------|------|------|--------|------|
| rangeType | String | 否 | `today` | 时间范围，见「六、日期范围」 |
| city | String | 否 | - | 城市筛选 |
| type | Integer | 否 | - | 展览类型筛选 |
| startDate | String | 否 | - | `rangeType=custom` 时的开始日期 |
| endDate | String | 否 | - | `rangeType=custom` 时的结束日期 |

**成功返回**：

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": {
    "todayVisitCount": 1268,
    "weekTicketCount": 1500,
    "weekRevenue": 264960.00,
    "refreshTime": "2026-10-15 10:30:00"
  }
}
```

| 字段 | 类型 | 对应原型 | 口径 |
|------|------|---------|------|
| `todayVisitCount` | Integer | 「今日到馆总人数 1268」 | `COUNT(*) FROM exhibition_order WHERE DATE(use_time) = CURDATE()` |
| `weekTicketCount` | Integer | 「本周售票总量 1500」 | `SUM(quantity) WHERE status IN (2,5) AND pay_time >= 本周一` |
| `weekRevenue` | Number | 「本周总营业额 ¥264960」 | `SUM(total_amount) WHERE status IN (2,5) AND pay_time >= 本周一` |
| `refreshTime` | String | 「手动刷新」后显示 | 本次统计时间 |

> 📌 **口径说明**：售出/营收只统计 `status IN (2,5)`（已支付、已完成）。待支付未付、已取消、已退款**都不计入**。

**SQL**：

```sql
-- 今日到馆（核销）人数
SELECT COUNT(*) FROM exhibition_order
WHERE DATE(use_time) = CURDATE();

-- 本周售票总量 + 营业额
SELECT COALESCE(SUM(quantity), 0)      AS ticketCount,
       COALESCE(SUM(total_amount), 0)  AS revenue
FROM exhibition_order
WHERE status IN (2, 5)
  AND pay_time >= #{weekStart};
```

### 2. 获取展览排行 🔒

- **Path**：`/api/admin/dashboard/exhibition-rank`
- **Method**：`GET`
- **描述**：数据看板下方排行表（排名 / 展览名称 / 累计售票数 / 客流占比）

**参数**：

| 参数名 | 类型 | 必须 | 默认值 | 说明 |
|--------|------|------|--------|------|
| rangeType | String | 否 | `today` | 时间范围 |
| city / type | - | 否 | - | 同上 |
| page | Integer | 否 | 1 | 页码 |
| pageSize | Integer | 否 | 5 | 每页条数 |

**成功返回**：

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": {
    "total": 12,
    "pages": 3,
    "page": 1,
    "pageSize": 5,
    "list": [
      { "rank": 1, "exhibitionId": 1, "exhibitionName": "咫尺千里", "ticketCount": 2200, "visitorRatio": 60.0 },
      { "rank": 2, "exhibitionId": 2, "exhibitionName": "水印木刻",   "ticketCount": 2110, "visitorRatio": 52.0 },
      { "rank": 3, "exhibitionId": 3, "exhibitionName": "艺海同辉",   "ticketCount": 1880, "visitorRatio": 45.0 },
      { "rank": 4, "exhibitionId": 4, "exhibitionName": "精品陈列",   "ticketCount": 1700, "visitorRatio": 40.0 },
      { "rank": 5, "exhibitionId": 5, "exhibitionName": "世界珍宝",   "ticketCount": 1560, "visitorRatio": 36.0 }
    ]
  }
}
```

| 字段 | 说明 |
|------|------|
| `rank` | 排名，由 Service 按 `(page-1)*pageSize + 下标 + 1` 计算 |
| `ticketCount` | 累计售票数 = `SUM(quantity)` |
| `visitorRatio` | **客流占比**，`该展览票数 / 全部售票总数 × 100`，保留 1 位小数 |

**SQL**：

```sql
SELECT e.id AS exhibition_id, e.title AS exhibition_name,
       COALESCE(SUM(o.quantity), 0) AS ticket_count
FROM exhibition_order o
JOIN exhibition e ON e.id = o.exhibition_id
WHERE o.status IN (2, 5)
  AND o.pay_time >= #{startTime} AND o.pay_time < #{endTime}
  AND (#{city} IS NULL OR o.gallery_id IN (SELECT id FROM gallery WHERE city = #{city}))
  AND (#{type} IS NULL OR e.type = #{type})
GROUP BY e.id, e.title
ORDER BY ticket_count DESC, e.id ASC
LIMIT #{offset}, #{pageSize};
```

> 📌 **客流占比必须在 Service 层算**：先查一次全部售票总数作为分母，再逐条算比例。SQL 里不做除法（避免分母为 0 的边界问题）。

## 三、展览管理

### 7. 展览列表分页 🔒

- **Path**：`/api/admin/exhibitions/page`
- **Method**：`GET`
- **描述**：展览列表（原型：展览ID / 展览名称 / 所属场馆 / 展期 / 票价 / 当日库存）

**参数**：

| 参数名 | 类型 | 必须 | 默认值 | 说明 |
|--------|------|------|--------|------|
| city | String | 否 | - | 城市 |
| status | String | 否 | - | **库存状态**：`all` 全部 / `available` 有票 / `soldOut` 已售完 |
| type | Integer | 否 | - | 展览类型 |
| keyword | String | 否 | - | 搜索展览（名称 / 编号） |
| page | Integer | 否 | 1 | 页码 |
| pageSize | Integer | 否 | 10 | 每页条数 |

**成功返回**：

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": {
    "total": 3,
    "pages": 1,
    "page": 1,
    "pageSize": 10,
    "list": [
      {
        "id": 1,
        "exhibitionCode": "NJ001",
        "title": "咫尺千里",
        "galleryId": 1,
        "galleryName": "江苏省美术馆",
        "startDate": "2026-05-01",
        "endDate": "2026-08-02",
        "price": 58.00,
        "dailyStock": 42,
        "stockStatus": "available",
        "stockStatusText": "42张"
      },
      {
        "id": 2,
        "exhibitionCode": "NJ002",
        "title": "水印木刻",
        "galleryId": 1,
        "galleryName": "江苏省美术馆",
        "startDate": "2026-07-01",
        "endDate": "2026-08-31",
        "price": 38.00,
        "dailyStock": 0,
        "stockStatus": "soldOut",
        "stockStatusText": "已售完"
      }
    ]
  }
}
```

| 字段 | 对应原型 | 说明 |
|------|---------|------|
| `exhibitionCode` | 「NJ001」 | `exhibition.exhibition_code` |
| `galleryName` | 「江苏省美术馆」 | JOIN `gallery` |
| `price` | 「¥58」 | 取自 `exhibition.price`（后台展示价） |
| `dailyStock` | 「42张」 | **当日剩余库存** |
| `stockStatusText` | 「已售完」 | **`已售完` 或 `N张`，服务端算好** |

**「当日库存」怎么算**：

```sql
-- 当日（或最近一个可预约日）该展览全部票种的剩余总量
SELECT COALESCE(SUM(c.total_stock - c.sold_count), 0)
FROM exhibition_calendar c
WHERE c.exhibition_id = #{id}
  AND c.calendar_date = #{nearDate};   -- nearDate = 最近一个 >= CURDATE() 的放票日
```

> **规则**：取该展览**最近一个放票日**的日历库存；全部票种剩余为 0（或该日不存在）→ `soldOut`。
> ⚠️ 这条要**批量查**（一次查所有展览的最近放票日剩余），不要在展览列表里逐条查（N+1）。

**SQL（主查询）**：

```sql
SELECT e.id, e.exhibition_code, e.title, e.start_date, e.end_date, e.price, e.daily_stock_limit,
       g.id AS gallery_id, g.name AS gallery_name, g.city
FROM exhibition e
JOIN gallery g ON g.id = e.gallery_id
WHERE 1 = 1
  <if test='dto.city != null'> AND g.city = #{dto.city} </if>
  <if test='dto.type != null'> AND e.type = #{dto.type} </if>
  <if test='dto.keyword != null'>
    AND (e.title LIKE CONCAT('%', #{dto.keyword}, '%')
      OR e.exhibition_code LIKE CONCAT('%', #{dto.keyword}, '%'))
  </if>
ORDER BY e.create_time DESC, e.id DESC
LIMIT #{offset}, #{pageSize};
```

> ⚠️ `status` 是**库存状态**不是数据库列，过滤要在 Service 层对结果集做（或改写成 `HAVING`/子查询）。

### 9. 新增展览 🔒

- **Path**：`/api/admin/exhibitions`
- **Method**：`POST`
- **描述**：新增展览页（基础信息 + 票务数据 + 每日票数上限 + 展览海报）

**Body**：

```json
{
  "title": "咫尺千里",
  "galleryId": 1,
  "startDate": "2026-05-01",
  "endDate": "2026-08-02",
  "type": 2,
  "openTime": "周二到周日 8:30-18:30",
  "dailyStockLimit": 200,
  "posterImage": "/static/upload/poster/xxx.jpg",
  "description": "展览简介长文…",
  "isHot": 0,
  "sortOrder": 0,
  "tickets": [
    { "name": "成人票", "price": 58.00, "totalStock": 500, "limitPerUser": 5 },
    { "name": "老人票", "price": 38.00, "totalStock": 300, "limitPerUser": 5 },
    { "name": "学生票", "price": 38.00, "totalStock": 300, "limitPerUser": 5 },
    { "name": "儿童票", "price": 38.00, "totalStock": 200, "limitPerUser": 5 }
  ]
}
```

| 参数 | 类型 | 必须 | 对应原型 |
|------|------|------|---------|
| title | String | 是 | 「展览名称 *」 |
| galleryId | Long | 是 | 「所属展馆 *」 |
| startDate | String | 是 | 「开展日期 *」 |
| endDate | String | 是 | 「闭展日期 *」 |
| type | Integer | 是 | 展览类型（原型顶部筛选） |
| dailyStockLimit | Integer | 是 | **「每日票数上限 *」**（最小值 1） |
| posterImage | String | 是 | 「展览海报 *」（先调接口 15 上传） |
| tickets | Array | 是 | 「票务数据」四个票价输入框 |
| tickets[].price | Number | 是 | 成人票必填，其余可空（空则不配该票种） |
| description | String | 否 | 展览简介 |
| isHot / sortOrder | Integer | 否 | 是否上首页热门 |

**成功返回**：

```json
{
  "code": 1,
  "msg": "新增成功",
  "data": { "id": 7, "exhibitionCode": "NJ007", "calendarGenerated": 94 }
}
```

| 字段 | 说明 |
|------|------|
| `exhibitionCode` | 后端按城市 + 序号生成（如 `NJ007`），运营不用手填 |
| `calendarGenerated` | **按展期自动生成的日历天数**（94 天 = 05-01 ~ 08-02） |

**新增时要做的 4 件事（同一事务）**：

```
① INSERT exhibition（exhibition_code 自动生成，daily_stock_limit 写入）
② INSERT ticket_type × N（每个非空票价一条）
③ 👉 按 [start_date, end_date] 循环 INSERT exhibition_calendar
      每天一条，total_stock = dailyStockLimit   ← 这就是「每日票数上限」的落地点
④ 同步 gallery.exhibition_count（若该展览在展期内）
```

> ⚠️ **第 ③ 步是关键**：新增展览页只填了一个「每日票数上限」，但 `exhibition_calendar` 是**按天存**的。
> 所以要在建展览时**批量生成整个展期的日历行**，每天 `total_stock = dailyStockLimit`。
> 94 天就是 94 行，用**批量 INSERT**（一条 SQL 多组 VALUES），不要在循环里逐条插。

**自动生成编号的规则**（建议）：

```
前缀 = 城市拼音首字母（南京 → NJ）
序号 = 该城市下现有展览数 + 1，补零到 3 位
→ 南京第 7 个展览 = NJ007
```

### 10. 编辑展览 🔒

- **Path**：`/api/admin/exhibitions/{id}`
- **Method**：`PUT`
- **描述**：修改展览信息

**Body**：同接口 9（不含 `tickets` 的 `totalStock` 可改，`soldCount` 不可改）

**成功返回**：`{ "code": 1, "msg": "修改成功", "data": null }`

**⚠️ 三个必须校验的点**：

| 场景 | 处理 |
|------|------|
| 展期被缩短 | 超出新展期的日历行：**已售出的不能删**（有订单），只标记 `status = 1` 停止发售 |
| 每日票数上限调小 | 只影响**尚未售出**的日期，`total_stock` 不得小于 `sold_count` |
| 票种被删除 | 已被订单引用的票种**不能物理删除**，改 `status = 1`（停售） |

### 11. 删除展览 🔒

- **Path**：`/api/admin/exhibitions/{id}`
- **Method**：`DELETE`
- **描述**：删除展览

**成功返回**：`{ "code": 1, "msg": "删除成功", "data": null }`

**失败返回**：

```json
{ "code": 0, "msg": "该展览已有订单，不能删除，请改为下架", "data": null }
```

> ⚠️ **有订单的展览一律不物理删除**（订单是财务数据）。检查：

```sql
SELECT COUNT(*) FROM exhibition_order
WHERE exhibition_id = #{id} AND status IN (1, 2, 5);
-- > 0 → 拒绝删除，提示改下架
```

### 12. 展览上下架 / 热门开关 🔒

- **Path**：`/api/admin/exhibitions/{id}/status`
- **Method**：`PUT`

### 21. 票务数据报表 🔒

- **Method**：`GET`
- **描述**：票务数据页表格（统计日期 / 展览名称 / 当日出售票数 / 当日核销票数 / 当日未核销票数 / 单日营收）

**参数**：

| 参数名 | 类型 | 必须 | 说明 |
|--------|------|------|------|
| city | String | 否 | 城市 |
| type | Integer | 否 | 展览类型 |
| keyword | String | 否 | 搜索展览 |
| startDate / endDate | String | 否 | 统计日期范围 |
| page / pageSize | - | 否 | 分页 |

**成功返回**：

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": {
    "total": 6,
    "pages": 1,
    "page": 1,
    "pageSize": 10,
    "list": [
      {
        "statDate": "2026-07-23",
        "exhibitionId": 1,
        "exhibitionTitle": "咫尺千里",
        "soldCount": 120,
        "verifiedCount": 112,
        "unverifiedCount": 8,
        "dailyRevenue": 6496.00
      }
    ]
  }
}
```

| 字段 | 对应原型 | 口径 |
|------|---------|------|
| `soldCount` | 「当日出售票数 120」 | `SUM(quantity) WHERE DATE(pay_time)=statDate AND status IN (2,5)` |
| `verifiedCount` | 「当日核销票数 112」（绿色） | `SUM(quantity) WHERE DATE(use_time)=statDate` |
| `unverifiedCount` | 「当日未核销票数 8」（红色） | `soldCount - verifiedCount` |
| `dailyRevenue` | 「单日营收 ¥6496」 | `SUM(total_amount) WHERE DATE(pay_time)=statDate AND status IN (2,5)` |

**SQL**：

```sql
SELECT DATE(o.pay_time)                     AS stat_date,
       e.id                                 AS exhibition_id,
       e.title                              AS exhibition_title,
       COALESCE(SUM(o.quantity), 0)         AS sold_count,
       COALESCE(SUM(o.total_amount), 0)     AS daily_revenue,
       COALESCE(SUM(CASE WHEN o.use_time IS NOT NULL THEN o.quantity ELSE 0 END), 0) AS verified_count
FROM exhibition_order o
JOIN exhibition e ON e.id = o.exhibition_id
WHERE o.status IN (2, 5)
  AND o.pay_time >= #{startTime} AND o.pay_time < #{endTime}
  AND (#{type} IS NULL OR e.type = #{type})
GROUP BY DATE(o.pay_time), e.id, e.title
ORDER BY stat_date DESC, sold_count DESC
LIMIT #{offset}, #{pageSize};
```

> ⚠️ 核销票数按**核销日期**算，但核销日期可能和支付日期不同天。上面按支付日分组会出现口径偏差。
> **准确做法**：分两次查（按支付日聚合 + 按核销日聚合），在 Service 层按「日期 + 展览」合并。
> 或者先按支付日聚合出「出售/营收」，再单独查一张「按核销日的核销数」映射表。

| 数据看板 | 三张卡片 + 排行，从 `exhibition_order` 聚合即可 |
| 票务数据 | 按日聚合，当前数据量实时算足够 |
| 核销记录 | 一单一码，`use_time IS NOT NULL` 即一条记录 |
| 展馆/展览列表 | 现有表 + `daily_stock_limit` 足够 |

> ⚠️ 若以后订单量上万导致报表变慢，再补一张按天汇总的 `ticket_daily_stats`（统计日期, 展览ID, 售出票数, 核销票数, 营收），由定时任务每晚汇总。

## 附录三：开发注意事项

| # | 注意事项 |
|---|---------|
| 1 | **B 端要单独写 `JwtTokenAdminInterceptor`**，用 `admin-secret-key` 验签，**adminId 不要写进 C 端的 `BaseContext`** |
| 2 | **新增展览时按展期批量生成日历行**（每天一条，`total_stock = dailyStockLimit`）。94 天 = 94 行，用批量 INSERT，不要循环插 |
| 3 | **「当日库存」要批量查**：列表页逐条查展览的日历库存会造成 N+1 |
| 4 | 「客流占比」在 Service 层算（需先查总数作分母），SQL 里不做除法 |
| 5 | `status` 是**库存状态**（已售完/有票）不是数据库列，过滤在 Service 层做 |
| 6 | **有订单的展览/展馆/票种一律不物理删除**，改下架或停售 |
| 7 | 调整库存 `total_stock` **不得小于 `sold_count`**，用条件更新判断影响行数 |
| 8 | 核销必须用 `UPDATE ... WHERE order_no = ? AND status = 2` 条件更新，防重复核销 |
| 9 | 核销成功后同步 `user.visit_count + 1`（C 端个人中心「观展次数」的数据源） |
| 10 | 退款审核通过要**同时回滚两个维度的库存**（`ticket_type` + `exhibition_calendar`） |
| 11 | 票务数据里核销数按**核销日**、售出按**支付日**，两者不同天，需分两次聚合再合并 |
| 12 | 展期缩短时，超出新展期的日历行**已售出的不能删**，只置 `status = 1` |
| 13 | 展馆的 `open_time`（C 端展示文本）由后端按 `closedDay + openHour + closeHour` 自动拼，运营不用手填 |
| 14 | 导出接口返回**文件流**，不套 `Result` 结构 |
| 15 | 「全部状态 / 全部类型」**不占枚举值**，前端加为第一项，选中时不传该参数 |
